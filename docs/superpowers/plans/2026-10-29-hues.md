# Task Tints Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Give Agent Wrangler tasks a persistent hue through a hexagonal colour wheel and Reset, preserving each theme surface's transparency.

**Architecture:** An ES-module extension owns its per-task colour store and graph contribution. The client contributes a task action and a zero-height task-body lifecycle, applying RGB-only CSS tints to task tiles and core minimised pills. A compact accessible dialog contains a honeycomb wheel.

**Tech Stack:** Node.js 20+, native ES modules, CSS relative colours, node:test; a DOM test dependency only if needed.

**Spec:** `docs/superpowers/specs/2026-10-29-hues-design.md`

## Global Constraints

- Extension id `hues`; label `Task Tints`; repository `psjamesh/agent-wrangler-task-tints`.
- Entry `Colour…` in existing task menus, a hexagonal colour wheel and `Reset`.
- Preserve original surface alpha, theme images and backdrop filters.
- Declare only `tasks:read`, `board:rebuild`, `board:broadcast`; host API `^1.53.0`.
- Keep terminal/chat backgrounds and session status styling unchanged.
- No unnecessary comments or runtime dependencies.

## Review Focus

- Translucent and transparent theme surfaces retain exactly their original alpha.
- Refreshing or minimising during an edit does not leave a picker or stylesheet behind.
- Simultaneous edits of different tasks preserve both values; stale acknowledgements do not affect another edit.
- Malformed ids/colours and failed disk writes do not mutate stored state or inject CSS.
- Switching themes and disabling/re-enabling Hues restores the correct current appearance.
